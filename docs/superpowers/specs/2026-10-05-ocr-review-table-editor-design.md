# P3 表格编辑器设计（OCR 审查页）

> 状态：**已与用户逐段对齐并获批（2026-10-05）**，待评审后转实施计划。
> 上游 spec：`docs/superpowers/specs/2026-10-04-ocr-review-block-editor-design.md`（§8.3 表格块 / §8.6 对齐 / §19 删除与物理清理 / §18 分期）。
> 本文件**只写 P3 增量与勘误**，不重复上游已定的内容。

## 0. 范围与出口判据

**做**：表格块的**就地编辑** —— 插入/删除行列、合并/拆分单元格、删除单元格内嵌图片、单元格文字对齐。

**出口判据（上游 §18 原文）**：「行列被当成图片塞进合并格」这一失效可被**完整修好**。

**不做**：公式（P4）、图片块编辑（P4）、**块级**增删（上游 §2.2 已判 YAGNI：新块在原 PDF 上没有 bbox，左栏无从高亮）。

## 1. 已核实的事实（实测，非推断）

| 事实 | 证据（2026-10-05 实测） |
| --- | --- |
| 表格块**曾经全部未定位** | `e9915ba8` 9/9 个 `table` 块 `start_line` 为 `None` ⇒ 既不能高亮、也**没有写回路径**（`splice` 靠行区间） |
| 根因：同一张表的**两种序列化** | md 侧带 `border/style`、跨多行、`<img>` 独占行；块侧是 OCR 给的**去样式、压成一行**的 `content` ⇒ 逐行比对必然全灭 |
| **该前提已在本轮修好** | 新增「按格内文字签名」兜底（`app/ocr/layout.py` 的 `_find_table_region`）：`e9915ba8` 锚定 **88/100 → 97/100**、missed **12 → 3**、`stale_anchors` **10 → 1**；`d66c2e0b` 表格 **24/24** 锚上，且**已锚定块的 span 变化 0 个**（纯加法） |
| **表格样式属性是边框与居中的唯一来源** | 库里含 `<table>` 的条文 **576 条，576 条带 `style=`、575 条带 `border=`**；渲染侧**无**补偿 CSS（`app.css` 只给 `.rvb-block-bd table { width: auto; max-width: 100% }`，`.clause-table` 是另一个 UI 组件，与条文内容无关） |
| 开标签只有 **3 种**形态 | `border=1 style='margin: auto; word-wrap: break-word;'` ×900 / `… width: max-content;` ×19 / `align="center" border=1 style='margin: auto; word-wrap: break-word;'` ×9 —— **三种都带 `border=1` 与 `margin:auto`** |
| 锚定基准是**库里的正文** | `layout.json.base_sha256` == `sha256(import_tasks.md_text)`；**磁盘** `data/outputs/{tid}/{tid}.md` 是**另一种文本**（实测 10239 vs 10449 行）⇒ 验证 span/行号必须读库里那份 |

> ⇒ **结论 1**：写回时**必须保留该表自己的开标签**，否则被编辑过的表会变成**无边框 + 左对齐**（用户可见的倒退）。这就是下面 §2 选 A 的依据。
> ⇒ **结论 2**：`block.content` 对表格**不可作为编辑源**（它是去样式版），编辑器需要 md 的那一份原文。

## 2. 设计

### §2.1 数据与落点

- **`_find_table_region` 顺手返回该区域的原文** ⇒ 表格块在 `layout.json` 里多一个字段 **`md_html`**（**只给表格块**，其它 label 不带）。
  - 该字段在**导入时**写入（`finalize_layout` 路径），请求期**不重算** —— 与 T1 接线同一口径。
  - `GET /import/review/{task_id}/layout` **不改结构**，只是 blocks 里多了这个键 ⇒ 前端透明。
- **编辑与写回都以 `md_html` 为源**：未编辑 ⇒ `splice` 原样取回 ⇒ **逐字节不变**；编辑过的表保留**它自己的**开标签。
- **写回复用既有通道**：编辑结果按 `edits[block_idx] = <序列化后的 HTML>` 提交，走既有 `compose → splice` ⇒ **后端零新增端点**。
- **存量**：`scripts/backfill_layout.py` 重跑一次即为既有任务补上 `md_html`（该脚本已具备指纹校验 / 幂等 / dry-run 三条护栏）。

### §2.2 编辑器形态（**中栏就地**，用户已定）

- 表格块点「纠正」⇒ 块内变成**表格编辑器**，复用现有编辑态的**保存 / 取消**按钮与语义（`editingIdx` 那套）。
- 渲染：`md_html` 解析成 `<table>`（走既有 `md-render.js` / DOMPurify 链，**不另起渲染路径**）；单元格 `contenteditable`；格内图片显示为缩略图。
- **按钮尺寸参考行编辑器**（`.rvb-tools` 的 0.72rem / 一行排下）。空间不足时**由用户折叠切分栏**腾出宽度（该能力已在 T7 交付），不为此另做响应式分支。

### §2.3 工具条与结构操作

按钮：`B ｜ I ｜ S ｜ 合并 ｜ 拆分 ｜ 插入行 ｜ 插入列 ｜ 删除行 ｜ 删除列 ｜ 左 ｜ 中 ｜ 右 ｜ 删图`

| 操作 | 语义（**逐条定死，避免实现歧义**） |
| --- | --- |
| 选择 | 点单元格 = 选一格；**Shift+点** = 以锚点到当前格为对角选**矩形区域** |
| 插入行 / 列 | 以**选区左上格**所在行/列为基准，插在其**前**；新格为空 |
| 删除行 / 列 | 删除选区**覆盖的全部**行/列（含只被覆盖一部分的） |
| 合并 | 选区 ≥ 2 格 ⇒ 左上格设 `rowspan=R`/`colspan=C`，**其余格删除**；保留左上格内容，被吞格内容丢弃 |
| 拆分 | 对选中格：按 `colspan/rowspan` 在**同行/同列**补出**空格**（HTML 不保存被吞格内容 —— 上游 §8.3 用户已接受） |
| 对齐（左/中/右） | 作用于**选区格内文字**（上游 §8.6）；**表格整体恒居中，不提供按钮** |
| 删图 | 删除选区格内的 `<img>` 元素；**不删文件**（上游 §19：物理清理在确认导入之后，编辑期必须可撤回） |
| B / I / S | 作用于单元格内的文字，复用行编辑器的 `execCommand` 路径与 `@mousedown.prevent` 处理（否则选区塌掉、命令无效） |

**DOM 即模型**：不另建表格数据结构，`<table>` 元素本身就是唯一真源；序列化 = `outerHTML` + 既有属性清洗。

### §2.4 撤销与保存前校验

- **整表快照栈**：每次**结构操作**（合并/拆分/插删行列/删图）前 `push` 一次表格 `innerHTML`；编辑器上一枚**「撤销」**按钮弹出（**不做** Ctrl+Z 全局拦截 —— YAGNI，且与浏览器/其它组件冲突风险高）。
- **保存前结构校验**，任一条不过 ⇒ **拒绝保存并给出可见原因**（绝不写坏 md）：
  1. 每行「`colspan` 之和」相等（矩形表；不等 ⇒ 表格渲染本就错位）
  2. 每格 `rowspan/colspan ≥ 1` 且不越出表的行列边界
  3. 网格占位无重叠、无空洞（用占位矩阵铺一遍验）
- 校验失败时**保留编辑态**（不退出、不丢用户改动），只在块内报错。

### §2.5 序列化契约（**「逐字节不变」的边界要说清**）

**未进入编辑态的块**：不产生 `edit` ⇒ `splice` 原样取回原行 ⇒ **逐字节不变**（上游 P0 的地基，结构上恒真）。

**进入编辑态并保存的块**：整块被序列化结果替换。序列化规则：

| 保留 | 丢弃 |
| --- | --- |
| `<table>` 自己的全部属性（`border=1` / `style='margin: auto; …'` / `align="center"`）**逐字保留** | 编辑器加的**一切痕迹**：`contenteditable`、选中态 class（如 `rvb-cell-sel`）、高亮包裹元素、为编辑插入的辅助节点 |

**已知且接受的行为（必须写进文档，否则会被当成 bug）**：md 里的表格可能是**跨多行**的（`e9915ba8` 实测跨 7 行），而 DOM 序列化出来是**单行 HTML** ⇒ **保存会把该表重排为单行**，即使内容一字未改。

- **语义与渲染不变**：两端都不解析表格（`parse_markdown` 按行切编号、`plain_text` 用 `HTMLParser` 剥标签，上游 §3.1），行数不参与任何判据。
- **代价**：确认导入后，该条文的 `content` 会出现一次纯空白差异（无害）。
- **不为此做特殊处理**：保留原换行需要维护「DOM 之外的原始空白」，收益为零、复杂度不低（YAGNI）。
- **可强化但暂不做**：保存时若序列化结果与 `md_html` **去标签间空白后**相同，则**不发 edit**（避免无谓重排）。留待有实际困扰时再加。

### §2.6 与切分预览的关系

表格块的 `md_html` 落在块的 span 内，`splice` 的替换是**整段**的 ⇒ 保存后 `schedulePreview()` 照常重算，**切分预览与实际入库条数的一致性（上游 §18 的 P2 铰链）自动延续**。表格 HTML 本身不产生新条文号，故不会改变切分结果 —— 这一点应写进探针断言（保存前后条号集合相同）。

## 3. 测试与验收

**单元/接口层**
- **往返回环**：`md_html` → DOM → 序列化，**未做任何编辑 ⇒ 与原文逐字节相同**（这是本设计的地基，必须是结构上恒真而非对拍）
- 合并：`rowspan/colspan` 数值正确、被吞格确实删除、左上格内容保留
- 拆分：补出的是**空格**、行列布局恢复
- 插删行列：位置正确（插在选区之前）、矩形性保持
- 删图：目标格内 `<img>` 消失、文件仍在盘上（`imgs/` 未变）
- **校验拒绝路径**：构造 `rowspan` 越界 / `colspan` 之和不等的表 ⇒ 保存返回可读错误、md **未被改动**

**探针（`scripts/probe_spec_ui.py`）** —— 真页面、真数据：
- 选中两格 → 合并 → 保存 → 块内容与切分预览同步；条号集合不变
- 删除一格内嵌图片 → 该 `<img>` 消失、其余格不动
- 对齐按钮作用于格内文字（读 computed style 断言）
- **出口判据走一遍**：拿 `d66c2e0b`（24 张表）或 `e9915ba8`（9 张表）里那张「图形」列全是 `<img>` 的表，用「删除列」或「删图」把误当成图片的行列清掉 ⇒ 表结构恢复正常

**风险与缓解**（表格 `rowspan/colspan` 是本套编辑器最易出错处）
1. **DOM 即模型** —— 不维护平行数据结构，避免两套账
2. **整表快照撤销** —— 结构操作可回退
3. **保存前严格校验** —— 非法结构挡在写盘之前

## 4. 依赖与前置

- **强依赖**：表格块必须先**可定位**（本轮已交付：`_find_table_region` 兜底 + `scripts/backfill_layout.py` 回填）。没有它，`md_html` 与 `splice` 写回都无从谈起。
- **依赖**：`compose`/`splice` 通道（P0 交付）、行编辑器的工具条与按钮处理（P2 交付）、切分预览（P2 交付）、三栏布局与折叠（P2.5 交付）。
- **不影响**：`md_parser`、`parse_markdown`、`plain_text`、数据库条文结构 —— 表格编辑后仍是**内联 HTML**，格式不变（上游 §3.1 结论）。
