# 部署与分享方案设计（grilling 收敛）

> 日期：2026-08-25
> 状态：设计稿（独立项目排期，暂不实施）
> 来源：grilling 技能审视「一键启动 + 分享 + agent 服务化」方向，14 个决策点收敛
> 范围：一键启动、分享部署、密钥安全、agent API（后续）

---

## 一、背景与目标

施工规范查询系统 V2 当前为本机自用。后续三个目标形态并存：

| 场景 | 使用方式 | 优先级 |
|------|---------|--------|
| 本机自用 | 人操作（浏览器） | 主 |
| 分享同事 | 浏览器查询（环境不可知） | 主 |
| agent 服务化 | API/MCP 供给 tool-call-agent | 升级功能，最后做 |

当前痛点：端口问题（uvicorn 双进程残留）、分享时密钥泄露风险、无适合 agent 的 JSON API 层。

## 二、端口方案

- **默认固定 8000**（本机/agent 用）
- 启动脚本检测到 8000 被**真正占用**时**自动 +1 找空闲端口**并打印实际地址（分享给他人时对方环境可能占 8000）
- agent 服务化时通过 `.env` / 启动参数显式固定端口
- **代码无 PORT 配置**（事实核实：全仓库 grep `8000`/`port` 零命中，端口纯靠 uvicorn CLI 参数）

## 三、安装器（引导式 exe）

**方案：PyInstaller 打包引导逻辑为 exe（不含 torch/模型，体积 ~10-50MB）**

安装流程：
1. **运行安装程序 → 自动检查系统环境**（Python 版本、已有依赖、模型是否已下载），已装的不重复装
2. **确认界面**：列出全部待安装内容，**复选框分「必选项/可选项」**
   - 必选：Python 环境（如缺）、requirements 依赖、代码 + 初始数据、BGE 模型
   - 可选：reranker 模型（提示「可提高检索和问答质量，硬盘足够建议安装」）
3. 执行：建 venv → `pip install requirements` → 从 ModelScope（优先）/HF（回退）下载模型 → 复制代码 + 数据 → 生成快捷方式/启动脚本

## 四、模型分发

- **默认只带 BGE**（`models/BAAI/bge-small-zh-v1___5`，清理冗余 `pytorch_model.bin` 后约 88MB）
- **reranker（1.1GB）作为可选增强**，提示文案「可提高检索和问答质量」
- 下载源：**ModelScope 优先，HuggingFace 回退**（与项目现有下载路径一致）

## 五、密钥与安全

- 分享版**清空 settings 表 API key 字段**（保留规范数据）；同事自配 AI/OCR key（不配也能用检索）
- **SECRET_KEY 强制**：config.py 改为「无 `.env` 提供 SECRET_KEY 时拒绝启动」，废弃公开默认值 `dev-secret-change-me`；部署首启自动生成随机密钥写 `.env`
- 预置 `admin` 账号 + **首次登录强制提示改密码**
- 引导页提示「配置 AI/OCR key 可用问答/OCR，不配也可用检索」

## 六、初始数据

分享前**先导入一批完整规范**再定版为初始数据（当前仅 2 本测试规范不够作为分享数据）。

## 七、agent API（后续，独立于本方案实施）

- **API 优先**（比 MCP 轻量，对单服务场景更直接）；MCP 作为将来需要时的 FastMCP 包装
- 新增 `/api/*` JSON 层 + `Authorization: Bearer` 认证（当前认证只认 cookie，不适合 agent）
- 排在「剩余优化方向完成后」实施

## 八、附带优化方向（后续待办）

- **检索模块二期上 CrossEncoder reranker**（一期只优化了 QA，检索页精排是下一站；与分享版 reranker 可选增强呼应）
- 用户使用说明书
- 登录页优化：支持修改用户名/密码

## 九、云服务器

**暂缓**。大部分用户为 Windows；Linux/systemd/Docker 部署轨道等本方案（Windows 引导式安装器）核心跑通后再加。

## 决策记录（grilling Q1-Q14）

| # | 决策 | 结论 |
|---|------|------|
| Q1 | 场景优先级 | 三者都要：自用 + 分享 + agent（最后做） |
| Q2 | 端口根因 | 残留进程（非配置）；分享场景需处理端口冲突 |
| Q3 | 分享对象 | 同事（同行业），浏览器查询，环境不可知 |
| Q4 | 端口方案 | 默认 8000 + 被占自动找空闲 + agent 固定 |
| Q5 | 部署形态 | 打包 A 首选（非局域网/云暂缓） |
| Q6 | 密钥安全 | 分享清 API key、保留规范数据 |
| Q7 | agent API/MCP | API 优先（更轻量）、后续做 |
| Q8 | 安装器形态 | 引导式 exe（不内置 torch/模型） |
| Q9 | 模型范围 | 默认 BGE + reranker 可选增强（带提示） |
| Q10 | 初始数据 | 分享前导入完整规范定版 |
| Q11 | 云服务器 | 暂缓 |
| Q12 | 模型源 | ModelScope 优先 + HF 回退 |
| Q13 | 安装器细节 | 环境检测 + 确认界面 + 必选/可选复选框 |
| Q14 | 首次部署 | 随机 SECRET_KEY + admin 首次改密码 + key 引导提示 |

## 实施阶段建议（暂缓，独立排期）

1. **阶段一（Windows 引导式安装器 + 密钥安全）**：config 强制 SECRET_KEY、分享版清 key、引导器 exe、环境检测 + 确认界面
2. **阶段二（初始数据定版）**：导入完整规范集 → 数据打包
3. **阶段三（agent API）**：`/api/*` JSON 层 + Bearer 认证（可选 MCP 包装）
4. **阶段四（可选）**：云服务器 Linux 部署（Dockerfile/systemd）
