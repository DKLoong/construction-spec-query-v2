## 一、硬证据：语料实测（2026-09-26）

### 1.1 语料构成

```
目录内 PDF 共 126 份
  ├ 像规范编号的（GB/JGJ/CJJ/JTG/JT/TB/DB/CECS…）: 59 份
  └ 非规范（公司文件/通知/作业指导书/指南）      : 67 份  ← 不会导入知识库
```

**教训**：任何"形态覆盖率"统计都必须先剔除非规范文档。本目录里
`中文顿号 20%`、`第X条式 11%` 两个形态**几乎全部来自非规范文档**。

### 1.2 形态 × 年代（仅文本层文件）

```
年代        份数  X.Y.Z  X.Y  X.0.Y  第X条  第X章/节  附录  罗马  中文顿号
1995-2007    2   2/2   2/2   2/2   0/2    0/2    2/2  1/2   0/2
2008-2019   10   7/10  7/10  5/10  0/10   3/10   6/10 2/10  0/10
≥2020        8   5/8   5/8   4/8   0/8    5/8    6/8  5/8   0/8
```

**三条硬结论**：

1. `X.Y.Z` / `X.Y` / `X.0.Y` / `附录` 在**最早的 1995-2007 规范里就已全部存在**
   → **编号语法跨年代稳定**，各版编写规则是叠加而非冲突
2. **`第X条` 在规范里 0 命中** —— 它只出现在非规范文档（公司文件/通知）
   → **不需要为它增加支持**（上一轮曾判断"要补"，已被实测否定）
3. **`中文顿号` 在规范里 0 命中** → **不做**（用户已裁定），且它本非规范形态

### 1.3 切分质量（CJJ 2-2008 / JGJ 107-2016）

```
                      CJJ2      JGJ107
源结构编号(去重)        850        84
库中条文号             754        73
召回                 744/850=87%  71/84=84%
  ├ 漏掉的「内节点」     103         12     ← 章名/节名
  └ 漏掉的「真叶节点」      3          1     ← 18.8.9 / 日期碎片2008 / 英文标题 ; 3.0.1
臆造出「数字编号」         0          0     ← 数字条文号切得很准
库中「不含数字的条文号」   123         2     ← 伪条文号（主控项目54/一般项目59/英文标题…）
「主控项目/一般项目」吞走的字符  209,366 = 全规范正文 47%
```

### 1.4 向量截断（检索质量的最大洞）

```
模型 BAAI/bge-small-zh-v1.5  max_seq_length = 512
附录A 的 embed_text 实测 1,624 tokens → 只保留 512 → 丢弃 68%
永不进向量索引的正文占比：CJJ2 = 67.2%   JGJ107 = 75.9%
```
（FTS 侧不受影响——`build_search_text` 不截断；所以现象会被混合检索掩盖。）

### 1.5 目次 vs PDF 书签（同一份 CJJ2，两条独立来源）

```
目次编号 135 个 | 书签编号 133 个 | 目次 ∩ 书签 = 133  →  书签 ⊆ 目次
仅目次有: 20.3、21.3（书签漏了这两个节，且 20.3 在正文里确实存在）
```
**结论**：**目次是超集、书签是子集**。书签不可靠有三重表现：漏节（20.3）、
全是占位（GB 50202-2018 的 95 条全是 `page-41`）、层级重复（低压配电 GB50054 的
L2/L3 是同一批节名）。→ 书签**不当真值、也不当输入**，最多做交叉校验的第二来源。

## 二、规则表

| # | 规则 | 依据 | 置信度 |
|---|---|---|---|
| R1 | 层次为 **章 / 节 / 条**；条可细分**款**，款可再分**项** | 编写规则 §层次划分（待核验） | 中 |
| R2 | 章/节/条编号用**阿拉伯数字**，圆点在**数字右下角** | 编写规则（待核验）；语料实测一致 | 高 |
| R3 | **章内不分节时，条号中对应节的位置用 `0` 表示**（`X.0.Y`） | 编写规则（待核验）；语料实测 `X.0.Y` 跨年代存在 | **高** |
| R4 | **款**=阿拉伯数字；**项**=带右半括号的阿拉伯数字（`1）`）→ **项属条内，不切分** | 编写规则（待核验）；语料实测括号序号多在条文内 | 高 |
| R5 | 附录：`附录A` / `A.2` / `A.2.1`；大写正体字母从 A 连续；**不得用 I、O、X** | 编写规则（待核验）；语料实测附录形态存在 | 中高 |
| R6 | 附录层次**最多 3 层**（正文最多 6 层） | GB/T 1.1—2020 第 7 章（待核验） | 中 |
| R7 | **次分组单元用大写罗马数字**（`Ⅰ 主控项目`），且**所属节的条文编号连续** → **不是层级，是条文属性** | 编写规则（待核验）；语料实测 41 份有书签的规范里「主控项目/一般项目」**0 命中**，可佐证其非层级 | **高** |
| R8 | `第X章` / `第X节` 是章/节的另一种排版 → 切分 | 语料实测（≥2020 规范里 5/8 份出现） | 高 |
| R9 | `第X条` → **不支持**（规范里 0 命中） | 语料实测 | 高 |
| R10 | `一、二、` 中文顿号 → **不支持**，非规范形态 | 语料实测（规范里 0 命中）+ 用户裁定 | 高 |
| R11 | **目次优先**：目录行（编号+点线+页码）应作为骨架来源，而非当噪声丢弃 | 语料实测（目次 ⊇ 书签；扫描件 OCR 亦可得） | **高** |

「置信度=高」= 有语料实测支撑，改 parser 时必须回归；
「中/中高」= 依赖待核验的编写规则原文，**取到原文后应回填**。
