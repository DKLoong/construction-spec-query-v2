## 二、转换方法（可复现，供将来处理同类文件）

| 输入 | 方法 | 结果 |
|---|---|---|
| Word `.doc`（码页 936/GBK） | `antiword -m UTF-8.txt file.doc` | ✅ 中文干净 |
| Word `.doc`（antiword 拒收，报 "is not a Word Document"） | PowerShell 内联 COM：`New-Object -ComObject Word.Application` → `Documents.Open(...)` → `SaveAs2(dst, 7)`（7 = wdFormatUnicodeText） | ✅ 成功（本机装有 Word） |
| PDF 文本层字体编码损坏（`犐犆犛` 应为 `ICS`，中文亦被映射成 `#$%&'()`） | **无解**（试过常数偏移解码：字母偏移并非常数、中文同坏）→ 只能 OCR | ✅ 本系统 PaddleOCR-VL：72 页 / **74 秒 / 93,390 字符** |
| 图片版 PDF | OCR | 同上 |

**踩坑记录**：
- `antiword` 只吃 OLE2 的 Word 文档；对某些 `.doc` 会直接拒收，此时 Word COM 是兜底
- 正则匹配章节标题时**必须先按行 strip** —— antiword 输出带大量行首空格，
  `^第[一二三四五六七八九十]+章` 会全部漏匹配（我在这里白跑了一轮）

## 三、结论：**本轮不需要按年份分派规则**（已由原文证实）

核心结论见 `parser-判定规则与依据.md` §二。要点：

- 1996 版与 2008 版的**核心编号语法完全一致**（章/节/条/款/项 + 阿拉伯数字 +
  无节用 `0` + 项用右半括号 + 附录字母从 A 连续）
- 2008 版只是**新增**三条：**次分组单元（大写罗马数字）**、**排除字母 X**、
  **单表/单图附录（表C/图C）** → **纯叠加，零冲突**
- 因此用**并集语法**（一套规则覆盖所有年代）即可，比"按年份分派"成本更低、
  覆盖更广，且避免「年份判错 → 整份规范判错」的风险
- 由比对直接推出的具体规则选择：**附录排除名单只取 `I`、`O`，保留 `X`**
  （1996 版不缺 X → 老规范可能有 `附录X`；按 2008 排除会误漏）

## 四、关于「用规范年份选规则」的核实

思路方向可行，但**本轮实测与原文比对都不需要它**。若将来真遇到「同形状异义」的冲突，
再启用，届时注意 3 个坑：

1. **年份 ≠ 起草时生效的版本**：编写规则在**起草期**就适用，而规范年份是**发布年**，
   通常晚 1~3 年。边界附近（如 2009~2011 年发布）会判错
2. **年份 ≠ 版本**：`GB 50204` 有 1992 / 2002 / 2015 三版，文件名只给一个年份
3. **有的文件名没有年份**：当前语料 59 份规范「未标年」为 0，暂不构成问题；
   但新语料可能出现（如 `T/CECS 382` 只给号不给年）

**若启用**：按「年份 + 边界年表（1996 / 2008-10-07 / 2009 / 2020-10-01）+ **±2 年缓冲**
+ 无法判定时回退并集」分派。
