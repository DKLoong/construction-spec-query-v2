## 四、核心结论：**本轮不需要按年份分派规则**

详见 `parser-判定规则与依据.md`。要点：

- **编号语法跨年代稳定**：`X.Y.Z` / `X.Y` / `X.0.Y` / `附录` 在 1995-2007 发布的规范里
  就已全部存在 → 各版本之间是**叠加关系，不是冲突关系**
- 因此用**并集语法**（一套规则覆盖所有年代）比"按年份分派"成本更低、覆盖更广，
  且避免「年份判错 → 整份规范判错」的风险
- 版本表的真正用途**不在编号识别**，而在**过滤与语义层**：非条文块名单（前言/目次/
  引用标准名录的命名随版本变）、章序约定（前三章叫什么）、附录规范性/资料性标注

## 五、关于「用规范年份选规则」的核实

你的思路方向可行，但有 3 个实操坑：

1. **年份 ≠ 起草时生效的版本**：编写规则在**起草期**就适用，而规范年份是**发布年**，
   通常晚 1~3 年。边界附近（如 2009~2011 年发布）会判错
2. **年份 ≠ 版本**：`GB 50204` 有 1992 / 2002 / 2015 三版，文件名只给一个年份；
   同一编号的历次版本须分别对待
3. **有的文件名没有年份**：当前语料 59 份规范「未标年」为 0，暂不构成问题；
   但新语料可能出现（如 `T/CECS 382` 只给号不给年）

**建议**：先上并集语法，把本谱系表作为**备查档案**。将来真遇到「同形状异义」的冲突，
再按「年份 + 边界年表 + ±2 年缓冲 + 无法判定时回退并集」分派。
